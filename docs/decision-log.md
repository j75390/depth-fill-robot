## 기록

### 2026-11-19 실행 환경
- 상황: 학습을 이 PC에서 할 수 있는지 먼저 확인해야 했다.
- 선택과 이유: PyTorch 2.11.0(CUDA 12.8 빌드)을 설치했다. 드라이버 610.88이 CUDA 12.8을 지원한다.
- 결과: `scripts/check_env.py` 기준 RTX 3060 Ti, VRAM 8.0GB, GPU 계산 확인 True.

### 2026-11-19 데이터: NYU Depth v2 labeled 1,449장
- 상황: 실제 센서(Kinect)로 찍은 정답 깊이가 있는 공개 데이터가 필요했다.
- 선택지: NYU Depth v2 labeled(약 2.8GB, 1,449장) / NYU raw 전체(수백 GB) / 합성 데이터만.
- 선택과 이유: labeled를 쓴다. 용량이 감당되고, **공식 학습 795장 / 시험 654장 분할(splits.mat)**이 있어서 시험 장면이 학습에 섞이지 않는다(같은 방의 앞뒤 프레임이 양쪽에 들어가는 누수를 피함).
- 전처리: 640x480 원본에서 값이 없는 흰 테두리를 흔히 쓰는 범위(행 45~470, 열 41~600)로 잘라 426x560을 만들고, 설정의 120x160으로 줄였다(가로세로 비율 차이 1% 미만). 한 번만 `scripts/prepare_nyu.py`로 npz를 만든다.

### 2026-11-19 정답 깊이의 함정: depths는 이미 채워진 값이다
- 상황: labeled의 `depths`는 센서가 못 잰 곳을 **색 기반 보간으로 이미 채운 값**이다. 그대로 정답으로 쓰면 "다른 알고리즘이 채운 값"을 맞히는 것을 평가하게 된다.
- 선택과 이유:
  1. 평가는 두 가지로 한다. 채운 정답 전체(MAE, RMSE)와, **센서가 실제로 잰 픽셀만**(MAE실측, RMSE실측). 결론은 실측 기준으로 낸다.
  2. 학습 손실도 실측 픽셀에서만 잰다(아래 모델 항목).
  3. 방법에 넘기는 입력도 원본 센서처럼 원래 못 잰 곳은 비워서 넘긴다. 입력 = 센서가 잰 값 − 우리가 뚫은 구멍.
- 줄일 때: `rawDepths`를 그냥 평균내면 0(측정 없음)이 섞여 값이 작아진다. 측정된 칸만 평균내고, 절반 넘게 빈 칸은 측정 없음으로 둔다(시험: `test_resize_raw_ignores_missing_values`).

### 2026-11-19 구멍 유형 추가: 실제 센서 누락(sensor)
- 상황: 기존 세 가지(무작위·가장자리·반사)는 사람이 정한 규칙이라 실제 누락과 다를 수 있다(계획서 한계 항목).
- 선택과 이유: 같은 분할의 **다른 장면에서 실제 누락 마스크를 빌려 와** 구멍으로 쓰는 `sensor` 유형을 더했다. 자기 장면의 누락은 쓰지 않는다(이미 비어 있어 평가가 안 됨). 학습은 학습 분할 마스크만, 평가는 시험 분할 마스크만 쓴다.

### 2026-11-19 모델 설계: 작은 U-Net, 가려 맞히기
- 입력: 깊이(÷10m, 값 없는 곳 0) + 값 있음 표시 1채널 = 2채널(모델 A), 여기에 컬러 3채널을 더한 5채널(모델 B). "값 없음"과 "깊이 0"을 구분하려고 표시 채널을 따로 둔다.
- 구조: 3번 줄이고 3번 키우는 U-Net, 첫 단계 32채널(약 1.9M 파라미터). 120x160에서 가장 작은 칸이 15x20이라 방 하나 규모의 맥락을 볼 수 있다. 8GB에서 배치 16이 여유 있게 들어간다.
- 학습: 매 배치 장면마다 구멍 유형 4가지 중 하나를 골라 가리고, **가렸지만 센서가 실제로 잰 픽셀**에서만 L1 손실을 잰다. 원래 비어 있던 곳(보간값)은 정답으로 쓰지 않는다. 좌우 뒤집기만 증강으로 쓴다(깊이의 의미가 바뀌지 않는 가장 단순한 변형).
- 고르기: 학습 분할의 10%를 검증으로 떼고, 검증 구멍을 고정해 에폭끼리 비교한다. 가장 좋은 검증 MAE의 에폭을 저장한다.
- 출력: 값이 있던 곳은 입력을 그대로 두고 구멍만 모델 값으로 채운다.
