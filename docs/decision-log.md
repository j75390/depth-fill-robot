## 기록

### 2026-11-19 실행 환경
- 상황: 학습을 이 PC에서 할 수 있는지 먼저 확인해야 했다.
- 선택과 이유: PyTorch 2.11.0(CUDA 12.8 빌드)을 설치했다. 드라이버 610.88이 CUDA 12.8을 지원한다.
- 결과: `scripts/check_env.py` 기준 RTX 3060 Ti, VRAM 8.0GB, GPU 계산 확인 True.

### 2026-11-19 데이터: NYU Depth v2 labeled 1,449장
- 상황: 실제 센서(Kinect)로 찍은 정답 깊이가 있는 공개 데이터가 필요했다.
- 선택지: NYU Depth v2 labeled(약 2.8GB, 1,449장) / NYU raw 전체(수백 GB) / 합성 데이터만.
- 선택과 이유: labeled를 쓴다. 용량이 감당되고, **공식 학습 795장 / 시험 654장 분할**(splits.mat)이 있어서 시험 장면이 학습에 섞이지 않는다(같은 방의 앞뒤 프레임이 양쪽에 들어가는 누수를 피함).
- 전처리: 640x480 원본에서 값이 없는 흰 테두리를 흔히 쓰는 범위(행 45~470, 열 41~600)로 잘라 426x560을 만들고, 설정의 120x160으로 줄였다(가로세로 비율 차이 1% 미만). 한 번만 `scripts/prepare_nyu.py`로 npz를 만든다.

### 2026-11-19 정답 깊이의 함정: depths는 이미 채워진 값이다
- 상황: labeled의 `depths`는 센서가 못 잰 곳을 **색 기반 보간으로 이미 채운 값**이다. 그대로 정답으로 쓰면 "다른 알고리즘이 채운 값"을 맞히는 것을 평가하게 된다.
- 선택과 이유:
  1. 평가는 두 가지로 한다. 채운 정답 전체(MAE, RMSE)와, **센서가 실제로 잰 픽셀만**(MAE실측, RMSE실측). 결론은 실측 기준으로 낸다.
  2. 학습 손실도 실측 픽셀에서만 잰다(아래 모델 항목).
  3. 방법에 넘기는 입력도 원본 센서처럼 원래 못 잰 곳은 비워서 넘긴다. 입력 = 센서가 잰 값 − 우리가 뚫은 구멍.
- 줄일 때: `rawDepths`를 그냥 평균내면 0(측정 없음)이 섞여 값이 작아진다. 측정된 칸만 평균내고, 절반 넘게 빈 칸은 측정 없음으로 둔다(시험: `test_resize_raw_ignores_missing_values`).

### 2026-11-19 구멍 유형 추가: 실제 센서 누락(sensor)
- 상황: 기존 세 가지(무작위·가장자리·반사)는 사람이 정한 규칙이라 실제 누락과 다를 수 있다(계획서 한계 항목).
- 선택과 이유: 같은 분할의 **다른 장면에서 실제 누락 마스크를 빌려 와** 구멍으로 쓰는 `sensor` 유형을 더했다. 자기 장면의 누락은 쓰지 않는다(이미 비어 있어 평가가 안 됨). 학습은 학습 분할 마스크만, 평가는 시험 분할 마스크만 쓴다.

### 2026-11-19 모델 설계: 작은 U-Net, 가려 맞히기
- 입력: 깊이(÷10m, 값 없는 곳 0) + 값 있음 표시 1채널 = 2채널(모델 A), 여기에 컬러 3채널을 더한 5채널(모델 B). "값 없음"과 "깊이 0"을 구분하려고 표시 채널을 따로 둔다.
- 구조: 3번 줄이고 3번 키우는 U-Net, 첫 단계 32채널(약 1.9M 파라미터). 120x160에서 가장 작은 칸이 15x20이라 방 하나 규모의 맥락을 볼 수 있다. 8GB에서 배치 16이 여유 있게 들어간다.
- 학습: 매 배치 장면마다 구멍 유형 4가지 중 하나를 골라 가리고, **가렸지만 센서가 실제로 잰 픽셀**에서만 L1 손실을 잰다. 원래 비어 있던 곳(보간값)은 정답으로 쓰지 않는다. 좌우 뒤집기만 증강으로 쓴다(깊이의 의미가 바뀌지 않는 가장 단순한 변형).
- 고르기: 학습 분할의 10%를 검증으로 떼고, 검증 구멍을 고정해 에폭끼리 비교한다. 가장 좋은 검증 MAE의 에폭을 저장한다.
- 출력: 값이 있던 곳은 입력을 그대로 두고 구멍만 모델 값으로 채운다.

### 2026-11-19 기준선: OpenCV Telea가 평균 채우기보다 나쁘게 나온 문제
- 상황: 시험 654장 첫 평가에서 OpenCV Telea의 구멍 오차가 약 0.9m로, 평균값 채우기(0.8m)보다 나빴다. 단순 채우기가 평균보다 나쁠 수는 없다고 보고 원인을 찾았다.
- 확인한 것: 구멍 속 **평균값은 정답과 비슷**한데 픽셀마다 0.6~3m로 튀었다. 같은 장면을 밀리미터 단위 `uint16`으로 넣으면 MAE 0.905m → 0.072m, Navier-Stokes 방식(float32)은 0.064m였다. 설치된 OpenCV 5.1에서 Telea에 float32 깊이를 넣을 때만 생기는 문제로 판단했다.
- 선택: 입력을 밀리미터 `uint16`으로 바꿨다. 같은 실수가 다시 들어오지 않게 "Telea가 평균 채우기보다 나아야 한다"는 시험(`test_opencv_telea_is_sane`)을 더했다.
- 결과: 고친 뒤 Telea가 가장 강한 기준선이 됐다(아래 표).

### 2026-11-19 1차 모델 결과: 두 U-Net 모두 Telea를 넘지 못함
- 설정: 위 모델 설계 그대로, 60에폭, 시드 42. 검증 MAE(가린 곳의 실측 픽셀) 깊이만 0.132m, 컬러 포함 0.129m.
- 시험 654장, MAE실측(m):

| 구멍 유형 | Telea | U-Net 깊이 | U-Net 컬러 |
|---|---|---|---|
| 가장자리 | **0.107** | 0.155 | 0.162 |
| 무작위 | **0.148** | 0.165 | 0.160 |
| 반사 면 | **0.072** | 0.099 | 0.095 |
| 실제 센서 누락 | **0.076** | 0.127 | 0.126 |

- 해석: 모델이 구멍 속 깊이를 **처음부터 통째로** 맞혀야 해서, 경계값을 그대로 이어 붙이는 Telea가 이미 잘하는 부분까지 다시 배워야 한다. 큰 오차(RMSE)는 무작위 구멍에서만 U-Net이 조금 낫다(0.259~0.264 대 0.284). 넓은 구멍의 큰 구조는 모델이 낫고, 세밀한 이어 붙이기는 Telea가 낫다는 뜻으로 봤다. 컬러를 더한 효과는 반사 면·무작위에서만 약간 있었다.
- 다음: 2차 개선으로 **Telea로 먼저 채운 깊이를 입력으로 주고, 모델은 그 위에 더할 보정값(잔차)만 배우게** 한다. 바꾸는 것은 이것 하나뿐이다(에폭·구조·시드 동일). 1차 체크포인트는 `checkpoints/v1/`, 결과는 `results/v1/`에 남긴다.

### 2026-11-19 2차 개선: Telea로 먼저 채우고 보정값(잔차)만 학습
- 바꾼 것: 깊이 입력 칸에 Telea로 먼저 채운 깊이를 넣고, 모델 출력은 그 위에 더할 보정값으로 바꿨다(설정 `train.prefill = "telea"`). 구조·에폭(60)·시드(42)·학습률은 1차와 같다.
- 검증 MAE: 깊이 0.132m → 0.090m, 컬러 0.129m → 0.094m.
- 시험 654장, MAE실측(m), 괄호는 Telea 대비:

| 구멍 유형 | Telea | U-Net 깊이(2차) | U-Net 컬러(2차) |
|---|---|---|---|
| 가장자리 | 0.107 | **0.105** (−2%) | 0.105 |
| 무작위 | 0.148 | **0.130** (−12%) | 0.132 |
| 반사 면 | 0.072 | **0.056** (−22%) | 0.057 |
| 실제 센서 누락 | 0.076 | 0.073 (−4%) | **0.073** |

- 우연한 차이인지 확인: 같은 장면끼리 짝지어 Telea와 비교했다(`results/paired_vs_telea.json`, 부트스트랩 2,000번). 네 유형 모두 평균 차이의 95% 구간이 0을 넘지 않는다(깊이 모델: 가장자리 −2.7mm [−3.0, −2.4], 무작위 −17.7mm [−19.3, −16.0], 반사 −15.9mm [−17.9, −14.1], 센서 −3.0mm [−4.1, −1.9]). 이긴 장면 비율은 84~88%인데 **실제 센서 누락만 60~64%**다.
- 품질 기준 시험(`scripts/quality_gate.py --model unet_depth --n 100`): 네 유형 모두 Telea보다 낮아 통과, API로 부른 결과와 직접 부른 결과의 최대 차이 0.5mm(밀리미터 반올림).

### 2026-11-19 컬러를 더해도 나아지지 않았다
- 결과: 2차에서 컬러 모델이 깊이 모델보다 나은 장면은 38~49%였고, 평균 차이는 −0.2 ~ +2.0mm로 오히려 약간 나쁘다.
- 해석(추측이며 확인하지 않음): 학습 장면이 716장뿐이라 컬러와 깊이의 관계를 일반화할 만큼 배우지 못했고, Telea로 먼저 채운 깊이가 이미 강한 정보라 컬러의 몫이 작다. 반사 면 구멍은 밝기로 골랐기 때문에 컬러가 도움이 될 거라 예상했지만 표에서는 보이지 않았다.
- 다음에 해 볼 것: 컬러 경로를 따로 둔 인코더, 더 많은 데이터(NYU raw 일부), 컬러 가장자리를 손실에 쓰는 방법. 이번 일정에서는 하지 않는다.

### 2026-11-19 실패 사례 분석
- 방법: 컬러 모델의 장면별 MAE실측 상위 4개를 그림으로 봤다(`docs/images/failures.png`).
- 공통점: 오차가 큰 장면은 모두 **구멍이 창문·유리 칸막이·먼 공간(4~5m 이상)처럼 깊이가 갑자기 멀어지는 곳을 넓게 덮었다.** 구멍 둘레가 가까운 물체(벽·선반)라 모델이 가까운 깊이로 이어 붙였고, 정답은 그 뒤의 먼 공간이었다(0.6~0.9m 오차).
- 의미: 주변 값으로 이어 붙이는 방식(Telea와 모델 모두)의 한계다. 로봇 입장에서는 "구멍이 경계를 가로지르는지"를 알려 주는 불확실도 출력이 있으면 이런 곳을 믿지 않도록 할 수 있다(향후 과제).

### 2026-11-20 품질 기준 시험을 시험 분할 전체로 판정하게 바꿈
- 계기: 시연 스크립트(`scripts/demo.py`)를 처음 앞 60장으로 돌렸더니 **실제 센서 누락** 유형에서 Telea 0.0633m, U-Net 0.0650m로 U-Net이 졌고 품질 기준이 실패했다. 전체 654장에서는 0.0761m 대 0.0731m로 이긴다.
- 해석: 이 유형은 이긴 장면이 60%라, 장면이 적으면 평균이 어느 쪽으로든 뒤집힐 수 있다. 결론은 654장으로 냈는데 기준 시험만 일부로 판정하면 앞뒤가 맞지 않는다.
- 결정: `quality_gate.py`의 기본값을 전체(654장)로 바꿨다(약 35초). `--n`은 빠른 확인용으로만 남겼다. 시연도 전체로 돈다(약 100초). 이 결과를 숨기지 않고 README·소개 페이지에도 적었다.

### 2026-11-20 세밀한 분석: 평균을 쪼갰다
- 계기: 평균 오차 하나로는 로봇에게 중요한 질문(가까운 물건, 빈칸 깊숙한 곳, 몇 cm 넘게 틀리나)에 답할 수 없다.
- 방법: `scripts/analyze.py`. 시험 654장 × 4유형, 실측 픽셀 642만 개를 **픽셀 단위로 모아** 계산(장면별 평균의 평균인 결론 표와 소수점이 다름). Telea·U-Net 깊이·U-Net 컬러.
- 결과(Telea → U-Net 깊이, 모든 유형 합계): MAE 10.4 → 9.2cm, 상대오차 3.9 → 3.4%, δ<1.05 80.5 → 83.5%, 5cm 초과 40.2 → 36.4%, 10cm 초과 24.0 → 20.7%.
- 빈칸 가장자리에서 안쪽 거리별: 1~2px −4%, 2~4px −7%, 4~8px −14%, 8~16px −18%, 16px 이상 −21%. Telea는 둘레 값을 이어 붙이므로 안쪽일수록 근거가 없어지고, 2차 모델(Telea + 보정값)은 그 안쪽을 고친다. 1차가 지고 2차가 이긴 이유와 맞는 그림이다.
- 실제 거리별: 1.5m 이내 −12%, 1.5~2.5m −17%, 2.5~3.5m −12%, 3.5~5m −7%, 5m 이상 −2%(둘 다 24cm 안팎으로 크게 틀림).
- 빈칸 크기 5~35%(모델은 15%로만 학습): 모든 크기에서 순서가 같다. 반사 면은 35%에서 10.2 → 7.7cm로 차이가 가장 크다.
- 해석: 두 방법 모두 빈칸 픽셀의 1/3 이상이 5cm 넘게 틀린다. 집기에 쓰려면 채운 값만으로는 부족하고 불확실도가 필요하다.

### 2026-11-20 학습 시드 3개: 대표 모델이 가장 잘 나온 경우였다
- 방법: 같은 설정으로 시드만 1, 2로 바꿔 두 번 더 학습(`train_unet.py --seed`). 검증 분할과 검증 구멍은 설정 시드로 고정해 같은 문제로 고르게 했다.
